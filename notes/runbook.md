Типовые сценарии диагностики Proxmox

## Сценарий 1: VM/контейнер не стартует
### Имитация
Удалён диск из конфигурации VM:
```bash
qm set 101 --delete scsi0
qm start 101
Симптом
VM «запускается» (статус running), но в консоли — зависание на этапе загрузки. qm start возвращает успех.

Диагностика
qm config 101 | grep -E "scsi|boot" — проверка конфигурации.

lvs — проверка, существует ли логический том vm-101-disk-0 физически.

journalctl -u pvedaemon --since "5 minutes ago" — ERROR отсутствует, Proxmox считает запуск успешным.

Консоль VM — единственное место, где видна реальная проблема.

Ключевой вывод
Не все проблемы логируются на хосте. Если VM «running», но не отвечает — смотри консоль VM, qm config и порядок загрузки (boot: order=...), а не только journalctl.

Решение
Проблема оказалась в порядке загрузки: в конфигурации стояло boot: order=ide2 (CD/DVD), а не scsi0 (диск). Исправлено командой:

bash
qm set 101 --boot order=scsi0
qm start 101
Также проверено, что диск на месте (lvs → vm-101-disk-0 существует) и привязан к VM (qm config 101 | grep scsi0).

Профилактика
После любых изменений в конфигурации проверять qm config 101 | grep boot.

При «странном» поведении VM всегда смотреть консоль, а не только статус.

Перед изменениями делать бэкап (vzdump).
## Сценарий 2: Закончилось место на диске
### Симптом
`apt install htop` завершается ошибкой:
E: You don't have enough free space in /var/cache/apt/archives/.

При этом пакет **не устанавливается**.

### Диагностика
1. `df -h` — показывает 100% использования корневого раздела.
2. `du -sh /* 2>/dev/null | sort -h` — находит файл, занявший место (`/root/bigfile`, ~3 ГБ).
3. **`journalctl -u pvedaemon` и `dmesg` пусты** — потому что apt сам проверяет место до записи и отказывается работать. Ядро и Proxmox в этом не участвуют.

### Ключевой вывод
Нехватка места не всегда логируется в системе. Если приложение «вежливо» отказывается работать из-за нехватки места, ошибка будет только в его выводе. Первый инструмент диагностики — `df -h`, а не логи.

### Решение
```bash
rm /root/bigfile
df -h
apt install htop
Профилактика
Мониторинг свободного места (алерт при < 10%).

Регулярная очистка /var/cache/apt/archives/ (apt clean).

Не хранить большие файлы в корне контейнера.
