Типовые сценарии диагностики Proxmox

## Сценарий 1: VM/контейнер не стартует
### Имитация
Удалён диск из конфигурации VM:
```bash
qm set 101 --delete scsi0
qm start 101
Симптом
VM «запускается» (статус running), но в консоли — зависание на этапе загрузки (No bootable device или подобное). Команда qm start возвращает успех.

Диагностика
qm config 101 — диск scsi0 отсутствует в конфигурации. Это первая зацепка.

qm status 101 — статус running, но это не значит, что система загрузилась.

journalctl -u pvedaemon --since "5 minutes ago" — ERROR отсутствует. Proxmox считает запуск успешным, потому что процесс QEMU жив.

Консоль VM — единственное место, где видна реальная проблема (нет загрузочного устройства).

Ключевой вывод
Не все проблемы логируются на хосте. Если VM «running», но не отвечает — смотри консоль VM и qm config, а не только journalctl. Ошибка может быть внутри гостевой системы, и Proxmox о ней не знает.

Решение
Вернуть диск в конфигурацию:

bash
qm set 101 --scsi0 local-lvm:vm-101-disk-0
qm start 101
Профилактика
Перед изменениями конфигурации делать бэкап (vzdump).

Вести документацию: какой диск (vm-101-disk-0) привязан к какой VM.

При «странном» поведении VM всегда проверять консоль, а не только статус.
