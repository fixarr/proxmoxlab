# Проблема с запуском KVM-виртуалки в Proxmox (вложенная виртуализация)

## Симптом
После создания KVM-виртуалки `test-vm` (Debian 13.7) в веб-интерфейсе Proxmox команда **Start** выполнялась успешно, но VM не запускалась. В окне консоли отображалось `Guest not running — Start now`, и запуск не происходил.

## Диагностика
1. Проверка `qm start 101 --debug` показала, что опция `--debug` не поддерживается в текущей версии `qm`.
2. Проверка настроек VM (`qm config 101`) показала, что по умолчанию используется аппаратное ускорение KVM.
3. Причина: Proxmox работает внутри VirtualBox. Вложенная виртуализация (nested virtualization) в VirtualBox не пробрасывает аппаратное ускорение AMD-V внутрь гостевой системы должным образом. KVM не может инициализироваться, и VM зависает в состоянии `Guest not running`.

## Решение
Отключить аппаратное ускорение KVM для конкретной VM и перевести её на программную эмуляцию QEMU. Также изменены тип CPU и сетевой адаптер для совместимости с VirtualBox.

Выполнено в консоли хоста Proxmox:

```bash
# Отключить KVM
qm set 101 --kvm 0

# Установить универсальный тип CPU
qm set 101 --cpu kvm64

# Сменить сетевой адаптер на e1000 (рекомендовано для вложенной виртуализации)
qm set 101 --net0 e1000,bridge=vmbr0
После этих изменений VM успешно запустилась. Установка Debian прошла, но заняла значительно больше времени из-за программной эмуляции.

Проверка
bash
qm config 101
В выводе должно быть:

kvm: 0

cpu: kvm64

net0: e1000,bridge=vmbr0,...

Выводы
В среде VirtualBox аппаратное ускорение KVM для вложенных гостей недоступно.

Для учебных целей KVM-виртуалки в VirtualBox работают медленно, но могут использоваться для понимания разницы между LXC и KVM.

Для дальнейшей практики рекомендуется использовать LXC-контейнеры, которые не требуют KVM и работают на полной скорости.

При работе на «голом железе» или в среде с поддержкой nested virtualization эти ограничения отсутствуют.

Профилактика
Перед созданием KVM-виртуалки в Proxmox внутри VirtualBox сразу отключать KVM (--kvm 0) и использовать CPU kvm64, сеть e1000.

Для повседневных задач использовать LXC.
